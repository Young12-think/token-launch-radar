A radar for token launches that have not happened yet. It reads a sealed snapshot of every protocol DefiLlama tracks (758 protocols, 14 Nov 2026), finds the ones with no token, and ranks them by what a launch would be worth — priced off a size curve fitted to the snapshot's own 92 launchable tokenised peers (log market cap on log TVL, residuals winsorised at 2σ), not by raw TVL and not by one stamped median multiple.

The point the ranking turns on: the obvious giants are not launchable. Wrapped Bitcoin, the big bridges, the liquid-staking receipts and the centralised exchanges hold most of the pre-token TVL, and a "launch" for them is meaningless — so this entry sets 144 of them aside with the reason stated, and ranks the remaining 198. The top of the board is Sentora Curator ($51M implied), Steakhouse Financial ($49M) and Gauntlet ($41M) — risk curators, not the wrapped assets every TVL-sorted list returns. Every row shows the curve value, the category-median multiple as a cross-check, and a farm plan built from that protocol's own record (category, chains, TVL tier, gas cost, cadence, exit) — never a repeated generic step. Each row also carries a one-line note saying why that cross-check multiple was used (peer-set size, fallback level, 25th/75th percentiles), and the top rows' farm plans name the real vault, market or mechanism instead of a generic template.

## Why the size curve (v3)

v1 priced every row off a category-median multiple. v2 tested that against a fitted size curve on the snapshot itself — leave-one-out over all 128 peers, and walk-forward (fitted on peers listed before 2025, tested on peers listed after). v3 changes the fitting population, not just the fit: the curve is fitted on the 92 priced peers that pass the same structural test the board applies, because bridges, staking wrappers and exchanges are priced off a different market-cap-to-TVL relation than anything the board ranks, and fitting on them pulled v2's curve toward assets the radar never prices. The residuals are winsorised at two standard deviations (four peers clipped: Bitway Earn, Concentrator, Kava Lend, Rain) and the line refit once; momentum is restored to full strength. Held out on the launchable peers: median log error 1.10 vs 1.71 for the v1 baseline leave-one-out (within-3x 50% vs 33%), 0.80 vs 1.59 walk-forward (within-3x 55% vs 35%). The slope is 0.41, so the implied multiple falls as TVL grows. The gain over v2 decomposes and is printed in the method note: the same v2 estimator on the launchable set scores leave-one-out within-3x 47.8% and walk-forward 55.2% (against v2's published 43.8% / 48.4% on all peers), and the winsorised fit plus full momentum lifts leave-one-out to 50.0% while walk-forward holds at 55.2%. A cross-check on all 128 priced peers still beats v2's published numbers (leave-one-out within-3x 45.3%, walk-forward 51.6%), so the improvement is not an artefact of changing the test set. Seasoning and chain breadth were re-tested on the v3 base and failed both tests again, so they stay dropped; momentum survived at full strength. The bear–bull band is the 25th–75th percentile of the model's own leave-one-out errors on the launchable peers (x0.348–x4.47), holding 51% of held-out tokens. The dashboard's integrity strip shows every check live, including a recompute of the top 5 rows from the curve itself. Farm verdicts (91 FARM / 57 MARGINAL / 50 SKIP) price gas cost against the position size only — the snapshot records no yield, so no return is ever claimed. Nothing here predicts whether or when a token will launch.

## Run it

```sh
mkdir -p out && MAKEFUN_OUTPUT_DIR=out node main.ts --input ../input/snapshot.json
```

Node 22, standard library only, no network. Writes `board.json` (198 rows, whole watchlist covered), `data.js`, `dashboard/` (a static page that renders offline from `data.js`), three screenshots, and `dossier.json` via the kit's `vendor/makefun-board.ts`. The dashboard is a dense data terminal — dark ink, one amber accent, no gradients, no hero — with an integrity strip (held-out validation, range calibration, coverage, farm verdicts, live recompute), sortable/filterable rows, a per-protocol detail view (the full arithmetic: size-curve value, category-median cross-check, full-strength momentum, farm economics), and the set-aside table with reasons.
